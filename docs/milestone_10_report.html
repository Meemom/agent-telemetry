Milestone 10: Broaden Assertions And Redaction

Implemented additional deterministic assertion types and expanded trace-time redaction so AgentTelemetry can catch more runtime policy violations while keeping sensitive payload data out of JSONL artifacts.

Branch milestone-10
Base milestone-9
Status Implemented

Assertion Schema

  • Updated src/agenttelemetry/model/test.py to accept node_reached, node_not_reached, error_absent, and max_tool_calls.
  • Added validation for required fields: node is required for node assertions, and max_count is required for max_tool_calls.
  • Kept tool optional for max_tool_calls so tests can cap either all tool calls or one named tool.

Assertion Engine

  • Updated src/agenttelemetry/runtime/assertions.py with deterministic evaluators for node reachability, error absence, and maximum tool-call count.
  • Added evidence event IDs for every new assertion path whenever matching runtime evidence exists.
  • Included the new assertion fields in stable assertion ID generation so reports distinguish tests with different nodes or limits.

Trace Redaction

  • Updated src/agenttelemetry/runtime/trace_capture.py to redact email addresses, SSN-like values, API-key-like tokens, and credit-card-like numbers before runtime events are written.
  • Added Luhn validation for credit-card candidates to reduce noisy redaction of ordinary long numeric strings.
  • Preserved redaction_mode=off for explicit unsafe local debugging while keeping strict as the default.

Tests And Docs

  • Expanded tests/test_assertions.py with coverage for all new assertion types and their evidence IDs.
  • Expanded tests/test_runtime.py to write a full-payload trace to trace.jsonl and verify raw sensitive values do not appear in the artifact.
  • Updated README.md with the new assertion types and redaction scope.
